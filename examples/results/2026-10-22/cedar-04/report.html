policy-scopeCandidate
You operate the fictional Cedar webhook adapter. Apply only the policy below, not a vendor's usual HTTP retry rules. Each event gets exactly three fields: terminal (boolean), retry (boolean), delay_seconds (integer). Terminal means the operation is recorded as successfully completed, not merely that processing stops. If retry is false, delay_seconds is always 0. If no rule applies, return terminal=false, retry=false, delay_seconds=0. Do not invent missing policy. Return only the requested JSON object, with no prose or code fences.
standard-retry-policyCandidate
A 2xx status is successful: terminal=true, retry=false. A 503 response is retryable only if an idempotency key is present. Such a retry is not terminal. For a permitted 503 retry, use the numeric Retry-After value in seconds, capped at 120 seconds; if absent use 17 seconds. Never convert seconds to milliseconds. For 503 without an idempotency key, do not retry and do not mark successful completion. A 429 response is retryable with a fixed delay of 31 seconds only when an idempotency key is present. Other 4xx statuses are not retryable unless an explicit exception below applies.
exception-policyCandidate
Exceptions take precedence over the standard policy. For HTTP 409, the exact error code DUPLICATE means the operation already completed: terminal=true, retry=false. Other 409 codes do not indicate success. For the tenant amber, any otherwise permitted 503 retry uses a fixed delay of 43 seconds, ignoring Retry-After and the missing-header default. This amber override does not grant permission to retry without an idempotency key. For any tenant with the manual_hold flag set, do not retry a 429 or 503 response, and do not mark it terminal. The hold rule takes priority over every retry rule.
operational-notesCandidate
Operational notes: Cedar is a training-only integration and no actual webhook will be sent. The team reviews aggregate delivery counts each Friday. Documentation uses green for successful deliveries and gray for pending ones. Event identifiers are labels, not priorities. Payloads may be inspected offline; never send a message or modify a live service while answering a policy question. These documentation conventions do not change any terminal, retry, or delay decision.

What this establishes—and what it does not

  • Fictional original policy, not a production trace or benchmark performance claim.
  • Reuses an existing model summary verbatim; all diagnosis trials are fresh. This is not continuation or pooling of earlier trials. The selected model settings describe diagnosis, not the earlier summary generation.
  • Exact JSON checks cover this batch only; strict formatting can also fail.
  • Filler matches characters, not tokens. Sequential repeated calls are not a significance test.
  • Task provenance: this is a human-authored fictional engineering policy with live model observations, not a production incident or an independently collected benchmark.
  • Summary length: 90 whitespace-delimited words; the 90-word target was met. The model output was used unchanged, including any length violation.
  • Budget accounting: 6/18 total calls, including 0 preflight calls (connectivity and compaction) and 6/18 diagnosis calls. The trial ledger below contains diagnosis calls; calls.json contains every call.
  • The displayed elapsed time covers the full experiment; diagnosis_elapsed_ms in report.json preserves the engine-only timing.
  • Evidence is specific to this task, evaluator, runner, snapshot, and append-at-end placement.
  • Candidates use whitespace-normalized substring matching, not semantic equivalence or contradiction detection.
  • Filler matches Python character count and newline positions, not model token count or semantic neutrality.
  • A 1-minimal repair means no single retained fragment can be removed at the chosen pass threshold; it is not a globally smallest repair.
  • Finite, sequential repeats and adaptive search do not establish statistical significance, reproducibility across seeds, or universal causality.
  • Completed arms are reused only within this run; repeats are separate calls, and stateful runners must be reset for each call.
  • Full restoration failure does not rule out other repairs, replacement rather than appending, or non-monotonic subsets.

Character-matched filler is not a token-matched placebo. Repeated observations are not a significance test, and 1-minimal is not globally minimum. Findings depend on the task, evaluator, runner, restoration position and sampled trials.
